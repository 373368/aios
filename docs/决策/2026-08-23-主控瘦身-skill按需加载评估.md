# 主控瘦身：skill 按需（延迟）加载机制评估

## 背景

主控上下文常驻 4 个 skill 目录 ≈54 个 description（custom 7 + ponytail 6 + agent-skills 24 + anthropic 17，合计约 5k token）。TODO #12 机制面 = 主控瘦身。

用户定案：**现在环境未到必须瘦身的程度**（54 个可接受），但未来 skills 必然增多，需未雨绸缪设计「按需延迟加载」机制。焦点评估：`@zenobius/opencode-skillful`。

## opencode-skillful 机制

- 实现 Anthropic Agent Skills Spec 的按需加载：`skill_find`（关键词发现）/ `skill_use`（加载 skill 内容进上下文）/ `skill_resource`（读 references/assets/scripts，预索引防路径穿越）
- 关键差异：内置 opencode = description 全部预注入（available_skills）；skillful = **描述也不预注入**，显式请求才加载
- **排他性**：真正省 token 必须把 `skills.paths` 从 opencode 配置移出、改由 skillful 接管扫描（否则内置描述仍注入，无收益）

## 评估结论：方向对，当前不安装

| 维度 | 判断 |
|---|---|
| 方向 | ✅ 描述级懒加载 = 未来扩容正解（内置机制无描述级懒加载，只有正文按需） |
| 排他迁移成本 | ⚠️ 需 54 skill 目录换扫描路径（默认只扫 `~/.config/opencode/skills` + `.opencode/skills`，需配 basePaths）+ 弃内置注入 |
| 许可 | ❌ npm 标 **Proprietary**，README 自称 MIT 不一致，dist 为混淆产物——与「开源参考实现」路线冲突 |
| 兼容 | ❓ 依赖 @opencode-ai/plugin 1.0.85，当前 opencode 1.17.11，插件 API 兼容未实测 |
| 维护 | ❌ 2026-02 后停更（6 个月），opencode 插件 API 演进中 |

## 触发条件与候选路径（未雨绸缪留档）

**触发阈值**：skill description 总量超过 ~10k token（约 100+ skill）时实施描述级懒加载。

**候选路径 A**：opencode-skillful——届时若插件 API 兼容且许可可接受。
**候选路径 B（推荐）**：自写轻量插件，用 `experimental.chat.system.transform` hook 把 skill 描述压缩为一行索引（name+关键词）注入 system prompt，需要时再 read SKILL.md。~50 行，无许可风险，适配当前 API，符合「核心逻辑通用化、宿主适配器自控」决策。

## 现状维持

- 54 个 description 常驻 ≈5k token，占比小，接受
- SKILL.md 正文已是按需加载（skill 工具触发才注入），无需改动
- 新增 skill 遵循统一目录（custom/AI-OS 面 + 通用面），触发词前置，控制描述长度

## 双方案定案（2026-08-23 用户收敛）

主控瘦身本质 = **两个正交杠杆，非二选一**：

| | 方案 2（职责层，为主） | 方案 1（token 层，兜底） |
|---|---|---|
| 思想 | 建立专用 subagents 分担不常用 skills（域隔离） | 从「何时加载」做文章 = 懒加载/按需加载 |
| 手段 | opencode 原生 subagent + permission.skill 白名单 + tools 过滤（dev.md 已示范） | 描述不预注入，skill_find/skill_use 按需取（skillful 类 / 自写 system.transform 索引插件） |
| 解决 | 主控职责膨胀、专长触发噪声、agent 提示词最小化 | 描述常驻 token |
| 现状 | 已建 kb-archivist（归档域）、dev（开发域） | 未启用 |
| 注意 | permission.skill 只控执行、**不控描述注入** → 行为隔离为主，token 靠方案 1 | — |

**组合路径**：职责层（方案 2）持续用 subagent 隔离专长域（推广 kb-archivist 模式）；skill 描述总量破 ~10k token（≈100+ skill）时再启用 token 层（方案 1）懒加载兜底。两层正交，可独立演进。
