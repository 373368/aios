# 2026-08-17 AI-OS 定性为 OS 内核（架构级转向）

## 背景

此前 AI-OS 以「agent」思维设计（L1 主控/编排、agent loop、分层蓝图）。2026-08-17 对话 dsh（DeepSeek Harness）调研 + 工作流触发方式解耦决策后，发现 agent 思维导致在错误的地方找答案（如"触发方式"在 OS 视角是调度器职责，天然解耦）。

## 决策

**LLM = 智能化 OS 内核。AI-OS 遵循 OS 设计哲学，而非 agent 设计。**

OS 抽象 → AI-OS 落点映射：

| OS 抽象 | AI-OS 落点 | 状态 |
|---|---|---|
| 内核（计算原语） | LLM（当前 DeepSeek，实现可换：DeepSeek/Qwen/本地） | ✅ |
| 调度器（触发层） | 外部触发：定时/事件/手动/另一程序 | ✅ 已解耦（见工作流触发方式解耦决策） |
| 进程 | 工作流（auto-archive 等完整独立组件） | ✅ 已组件化 |
| 地址空间 | 记忆三层拓扑（显式/语义/行为） | ⚠️ 知识层设计中 |
| 文件系统 | Obsidian vault | ✅ |
| 系统调用 | MCP 工具 | ✅ |
| 设备驱动 | MCP 服务器 | ✅ |
| 用户态/内核态 | 权限边界（确认/回滚/审计） | ⚠️ 自用默认：全权限 + kb-archivist 子代理白名单；审计待实现 |
| **逻辑中心** | **agent loop（有逻辑中心、无实现特权）** | 🔲 待固化 |

## 「有逻辑中心，无实现特权」（比"无中心"精确）

- **逻辑中心必须存在**：接收反馈/综合决策/派发——dsh 的 agent loop / shared context 就是，无它则只是空壳事件总线
- **实现特权可以没有**：loop 本身也是插件，实现可替换（类比：LLM=CPU 必须有，但 x86/ARM 都行）
- 修正：此前"无特权核心"表述不准确，应改"有逻辑中心，无实现特权"

## 与 dsh（DeepSeek Harness）同构性

| dsh | AI-OS |
|---|---|
| Everything is a Plugin | 组件化可插拔 |
| 事件驱动（session/agent/capability 三类事件） | 触发层解耦 = 调度器职责 |
| Session log 事件溯源（Model-visible means logged） | opencode.db 的 session/message/part 表 |
| 无特权核心（有不可替换前提） | 有逻辑中心、无实现特权 |

## 落地

- `01-分层蓝图.md` 顶部新增「OS 内核视角」重构节（L1-L4 保留为实现视图）
- 记忆引擎（第二步）定位强化：= 内存管理单元（地址空间 + 行为拓扑驱动决策）
- 权限边界（用户态/内核态）与危险操作确认/审计为系统层原生职责

## 影响

- **不在错误的地方找答案**：任何"谁来调度/谁触发"问题 → 调度器层；任何"记忆如何影响决策" → 地址空间层
- 宏观设计（spec 边界"Ask first"）已确认，本次为已批准的宏观设计更新
