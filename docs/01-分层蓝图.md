# AI OS — 架构分层蓝图

## 0. OS 内核视角（2026-08-17 架构级定性）

> 决策记录：`04-项目/ai-os/04-决策记录/2026-08-17-AI-OS定性为OS内核.md`

**LLM = 智能化 OS 内核。AI-OS 遵循 OS 设计哲学，而非 agent 设计。** 本视角是架构定性（坐标），下文 L1-L4 是实现视图。

| OS 抽象 | AI-OS 落点 | 状态 |
|---|---|---|
| 内核（计算原语） | LLM（当前 DeepSeek，实现可换） | ✅ |
| 调度器（触发层） | 外部触发：定时/事件/手动 | ✅ 已解耦 |
| 进程 | 工作流（auto-archive 等独立组件） | ✅ |
| 地址空间 | 记忆三层拓扑（显式/语义/行为） | ⚠️ 知识层设计中 |
| 文件系统 | Obsidian vault | ✅ |
| 系统调用 | MCP 工具 | ✅ |
| 设备驱动 | MCP 服务器 | ✅ |
| 用户态/内核态 | 权限边界（确认/回滚/审计） | ⚠️ 自用默认：全权限 + kb-archivist 子代理白名单；审计待实现 |
| **逻辑中心** | **agent loop（有逻辑中心、无实现特权）** | 🔲 待固化 |

**核心修正**：有**逻辑中心**（接收反馈/综合决策/派发，必须存在），无**实现特权**（loop 本身可替换）。类比：LLM=CPU 必须有，但 DeepSeek/Qwen/本地均可。

**设计含义**：
- 任何"谁来调度/谁触发"问题 → 调度器层（外部，非工作流内部）
- 任何"记忆如何影响决策"问题 → 地址空间层（记忆引擎 = 内存管理单元）
- 权限边界 = 系统层原生职责（危险操作确认/回滚/审计），非 agent 临时策略

## 0.5 面板底座视角（2026-09-05 演进，万物皆插件）

> 决策记录：`04-项目/ai-os/04-决策记录/2026-09-05-万物皆插件-面板底座定性.md`

**面板 = 硬件底座 = 环境。环境独立成立；加进去的一切都是插件（LLM/agents/工具/原语/MCP/工作流/ATS 均不同等级外层插件，连实现任务核心的部分也是）。**

- **底座剩什么（协议+机制，非功能）**：接入协议（统一注册面）/ 总线（通信事件通路）/ 会话 / 持久化槽位（registry+event ledger，状态可重建）/ 权限边界
- **功能全可加装**：goal/协调/记忆策略/工作流定义都是插件，不是环境本身
- **防退化三义务**：接入协议统一 / 事件可溯源 / 状态可重建
- **选型判据**：组件属核心 ⟺ 属"状态/调度/协调/环境机制"；其余按插件分级（核心/常用/一次性），现成优先可换优先
- **评估现成系统**（如 loopx）：取它的协议层做底座，其余当可换预装插件

## 核心原则

1. **透明覆盖，而非替换**：AI 层掌握主控，底层 OS 原样保留
2. **记忆驱动决策**：记忆不只存档，直接参与操作决策链
3. **扩展可插拔**：同一核心，不同分支换扩展

## 分层总览

```
┌─────────────────────────────────────────────────┐
│  L1  AI 主控层（opencode + 编排）                 │
│     意图理解 / 任务规划 / 决策执行 / 自主编排       │
├─────────────────────────────────────────────────┤
│  L2  记忆层（Obsidian + mcpvault + 三层拓扑）     │
│     显式拓扑 / 语义拓扑 / 行为拓扑                 │
├─────────────────────────────────────────────────┤

│     windows-mcp / mcpvault / playwright / ...    │
├─────────────────────────────────────────────────┤
│  L4  OS 层（Windows 本体）                        │
│     应用 / 文件 / 进程 / 服务 / 网络 / 可视化       │
└─────────────────────────────────────────────────┘
```

## 各层职责与依赖

### L1 AI 主控层
- **职责**：听懂用户意图 → 规划任务 → 决定动作 → 调 L2/L3 → 汇报
- **技术**：opencode（CLI TUI）、`opencode run`（headless/定时）、agents/subagents
- **决策链**：当前情境 → 查询记忆(即"寻址") → 记忆软激活影响决策 → 动作 → 写回
- **安全**：危险操作前向用户确认（第一版），回滚/审计后续

### L2 记忆层（核心原创）
- **显式拓扑**：Obsidian 双链/标签/目录 —— 人类手写地址结构
- **语义拓扑**：embedding 索引（笔记向量 + 距离核）
- **行为拓扑**（空白/原创）：记录"哪组笔记常在操作中一起出现、顺序"，AI 实跑后浮现
- **接口**：mcpvault（读写）、检索（BM25→语义分层演进）
- **对应**：用户参数域设想"地址空间+MLP+软激活"的系统域落地

### L3 工具层
- windows-mcp：UI控制 + 文件/进程/注册表/服务/截图
- mcpvault：vault 读写
- playwright：浏览器
- github/kaggle/wps-office/…：按需挂载
- **插拔规则**：MCP 服务器即能力单元，分支差异体现在挂载哪些

### L4 OS 层
适配：Windows 10/11。AI 拥有用户全部权限 + SYSTEM 用户态管理权（非内核）。

## 数据流示例：最小闭环（周报）

```
用户: "整理本周知识成周报"
  ↓
L1: 意图理解 → 规划整理步骤
L1: 向 L2 查询"本周新建/修改笔记"（寻址）
L2: 语义+显式检索 → 返回候选笔记
L1: 决策 (归纳主题/关键词/双链/下周待办)
L2: 读具体笔记 → L1 归纳 → 写回 03-日志/周报
L2: 记录本次决策过程 = 行为拓扑首桶数据
L1: 汇报完成
```

## 多分支扩展矩阵

| 分支 | 目标用户 | 扩展（L3 挂载 / L1 能力） | 基础层差异 |
|---|---|---|---|
| 通用版 | 个人知识管理 | 默认核心（记忆+编排+基础控制） | 无 |
| 视觉增强版 | 界面/设计工作者 | + OmniParser/UI-TARS 视觉理解 | 无 |
| 开发者版 | OS/后端开发者 | + 服务/设备/调试/容器/DISM 纵深工具 | 无 |
| (远期) 研究版 | 研究者 | 行为拓扑数据 → 分析导出 | L2 深度 |

各分支共享 L1 核心 + L2 记忆架构，仅 L3 挂载与 L1 技能集不同。

## 里程碑（由可行性结论延伸）

- **M1（当前）**：第一版最小闭环（周报+行为记录）→ 验证 L1+L2+L3 链路
- **M2**：定时无人值守（计划任务调度周报/整理）
- **M3**：视觉增强插件（针对敏感界面）
- **M4**：危险操作确认/回滚/审计
- **远期**：行为拓扑建库、多分支产品化
