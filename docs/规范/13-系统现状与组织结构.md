> 定位：AI-OS 当前阶段的**实际文件/能力/工作流/规范盘点**。每项标注「可编程化程度」（已原语化 / CLI 脚本 / LLM 判断点），是「从 skill 内嵌 → 确定性原语」演进的真实基线。
> 依据：2026-08-22 实测盘点 + 12-原语与SDK扩展规范。

## 1. 总体架构（OS 定性落地 · 三层：原语/工作流/SDK）

```
LLM 核心（opencode agents，判断点自治，直接持有 SDK 运行元件）
        ▼
[SDK 层]（LLM 参与的整合监控层——概念定位，尚未实体化）
  └─ 工作流控制 / 多工作流整合 / 错误与意外处理 / 高层复杂处理
        ▼ 驱动
[工作流层]（声明式 YAML 编排 + 锁/日志/退出码）
  ├─ wfengine.py 执行 archive-daily / digest-daily / track-daily（YAML 声明式，推荐形态）
  ├─ command: archive / distill / distill-h3 / search-enhanced（旧入口）
  └─ track-*.ps1 / auto-archive.ps1（纯编排壳）
        ▼ 调用
[原语层]（= 工具统一体，scripts/ + tasks/ + MCP + stdlib）
  ├─ primitives.py（写操作 5 原语）
  ├─ sys_classify_sdk.py（分类固化 4 原语）
  └─ 独立脚本原语：scan_new / build_index / search_index / chunk_sessions / embedders / fetch_*
        ▼
资源层
  ├─ vault（05-知识 601 页 + 01-记忆 8 页 + 06-系统 8 页 + 03-日志）
  ├─ index（qwen 629 页索引，fd_bm25 v1 引擎）
  └─ export / chunks（工程中间态）
```

## 2. 可编程化程度矩阵（核心现状）

| 面 | 已原语化（确定性函数） | CLI 脚本（入口契约符合） | LLM 判断点（不可/不必原语化） |
|---|---|---|---|
| 归档提炼 | write_kb_page / append_behavior_log | scan_new / chunk_sessions / build_index / export-* | 提炼价值、主题、骨架归类、去重语义 |
| 记忆沉淀 | write_memory_page / mark_digested / append_digest_log | build_index | 归属分类（知识/记忆/待办） |
| 分类固化 | classify_sys / extract_anchors / extract_harden / extract_skill_cands | — | 精判候选、确认落盘去向 |
| 检索 | — | search_index（fd_bm25 v1） | 查询意图 |
| H3 追踪 | fetch_arxiv / fetch_github / fetch_journal | track-journal/arxiv/github.ps1（纯编排壳） | 价值判断、提炼 |

**演进状态**：写操作 100% 原语化（primitives.py）；判定类 50% 原语化（sys_classify 机械初判 + LLM 精判）；读/索引/抓取为 CLI 脚本（已符合 05-规范「单一入口/退出码」）；**判断点全部保留 LLM**（这是设计：原语管执行，LLM 管判断）。
