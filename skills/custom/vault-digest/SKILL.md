# Vault Digest — 知识沉淀机制

## 目标

将完成后的临时信息按《记忆-知识分类规则》从 memory 沉淀进 vault 长期知识库。事件驱动实时执行，非定时任务。

## 触发时机（事件驱动）

- **完成待办后**：某事项做完，其"结论/理由 why"立即归档
- **会话收尾**：/remember 时检查是否有可沉淀项（是否沉淀由记忆引擎的「沉淀触发规则」裁决，见 `06-系统/沉淀触发规则.md`）
- **用户指令**："沉淀" / "归档" / "/digest"
- **统计前预清理**：周报统计自动先跑一次 digest（保证统计基于已沉淀状态）

## 流程（幂等，可中断恢复）

### 1. 扫描待归档源
检查这些临时位置是否有"已完成、不再变化"的内容：
- `<repo>\l1-control\opencode\.opencode\memory\` 下 `status: active` 的待办结果
- `00-收件箱/` 下的笔记
- 会话中形成但未归档的结论

> **注意：`<repo>\l1-control\opencode\.opencode\memory\TODO.md` 是永久待办文件，永不过期、永不被 digest**。其中的事项只标记 `[x]`（done），前不加 `[ ]`，绝不允许重命名为 `.digested.md` 或删除。

### 2. 逐条判定归属（按分类规则）
对每个候选项问：**"是领域知识 / 有价值的会话工作记忆 / 仍在进行的待办？"**
- 领域知识（用户学的、以后永远成立的事）→ 写入 `05-知识/知识库/` 对应主题页
- **有价值的会话工作记忆**（完整已完成的会话过程记录，类似 dsh session log："这次会话做了什么/怎么排查过/为什么这么选"；**非领域知识提炼**）→ 写入 `01-记忆/<主题>.md`，每主题一页 + frontmatter(type: memory) + 相关双链，与知识库同构。**仅有价值、能产出知识的会话才记**，不是所有会话都记
- 待办（进行中）→ 留在 memory，不动

**归属落点（两级兜底，统一命名"其他"）**：
- 能归骨架且能归子目录 → `<骨架>/<子目录>/`
- 能归骨架但不能归子目录 → `<骨架>/其他/`
- **不能归任何骨架**（如经济学/法律/心理学等新领域）→ `05-知识/知识库/其他/`（跨骨架兜底），并补 frontmatter `category: 待归类`，后续由记忆引擎按语义检索归位或人工处理
- **禁止**：知识页不许留在骨架顶层游离（顶层只有 `00-骨架.md` 和 9 骨架目录 + 其他）

### 3. 去重与链接
- 写知识前先 search 现有的（mcpvault search / grep），避免重复条目
- 归档时补 frontmatter（created/updated/type/topic）+ 相关双链
- **用原语库落盘**：`from primitives import write_kb_page, write_memory_page`（`<repo>\l2-memory\scripts\primitives.py`）——领域知识页走 `write_kb_page`，01-记忆 页走 `write_memory_page`（自动 type: memory），格式/幂等/原子写由函数保证

### 4. 清理临时源
- memory 中已沉淀项：用原语库 `mark_digested(path)` 重命名为 `<原名>.digested.md`（文件内容不动，不删除原文，留轨迹）。重命名即标记：/recall 只看文件名即可跳过，无需逐个读文件内容省 token
- 收件箱已处理项移到对应域或标记

### 5. 记录动作
用原语库 `append_digest_log(summary="沉淀X项 / 归档Y链接 / 跳过Z(仍在进行) / 去重W", completed=是否完整跑完)` 追加 `03-日志/digest-<YYYYMMDD>.md`（完整跑完写 COMPLETED 标记，中断恢复靠它）

### 6. 刷新语义索引（沉淀即索引）
沉淀写入 `05-知识/知识库/`、`01-记忆/` 后，必须同步刷新语义索引，否则检索结果滞后（build_index.py 已含 01-记忆 扫描源，前缀区分 05-知识/01-记忆/06-系统）：
- 执行：`python <repo>\l2-memory\scripts\build_index.py`
- **增量模式**（默认）：sha 比对，只 embed 新增/变更页，未变页零 API 调用，秒级
- **强制全量**：`--full`（embedder 模型/维度变更时用）
- key 从 `<repo>\l2-memory\config.json` 读（已配置，无需操作）
- 失败不阻断：索引刷新失败仅记录到 digest 日志，下次 digest 会重试（幂等）

## 中断恢复（关键）

计划任务/会话可能中断。可靠性设计：

1. **幂等**：每项处理前先检查目标是否已存在（同 topic 页搜到内容一样 → 跳过）。重复跑不产生重复。
2. **断点可续**：digest 日志即断点。再跑时读 `03-日志/digest-*.md` 尾部：
   - 若上次中断（无 completion 标记）→ 从上次处理项续跑
   - 每次完整跑完在日志尾写 `COMPLETED <时间>`
3. **不删源原则**：沉淀只做"写知识+标记 digested"，绝不删除 memory 原文。中断后原文仍在，不会丢数据。
4. **原子写入**：知识页写入用"先写临时→验证→再替换"（避免半截文件）。
5. **失败可见**：异常项写入 `05-知识/_digest-errors.md`（含原因），不静默吞掉。

## 验收

- [ ] 完成待办 → 对应结论出现在 05-知识 且 memory 有 digested 标记
- [ ] 同一项反复触发 digest 不产生重复知识页
- [ ] 中断重跑能从断点续，不丢不重
- [ ] digest 日志可回溯每次做了什么
- [ ] 沉淀后语义索引自动增量刷新（检索能命中新页）
- [ ] 索引刷新失败不阻断 digest，留痕可重试
